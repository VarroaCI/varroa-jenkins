{{- if .Values.networkPolicy.enabled }}
================================================================================
  NetworkPolicy
================================================================================
  NetworkPolicy is ACTIVE (networkPolicy.enabled=true).
  • By default, NetworkPolicy is opt-in (enabled: false). Enable only after
    verifying cluster CNI compatibility.
  • networkPolicy.ingressControllerNamespaceSelector controls which namespace
    can reach ingress-exposed services (default: ingress-nginx). Tune to match
    your ingress controller's namespace.
  • networkPolicy.tenantNamespaceSelector controls which tenant/controller
    namespaces can reach the gateway on :9090 (gRPC) and :9092 (apikey verify).
    Default: {} = all namespaces.
  • kubelet liveness/readiness probes are assumed CNI-exempt (Calico, Cilium
    default). Clusters that enforce NetworkPolicy on kubelet-originated traffic
    need a node-CIDR ingress allowance (not shipped).
  • networkPolicy.apiServerEgress.cidrs defaults to ["0.0.0.0/0"], which
    allows every address on ports 443 and 6443. Pin each endpoint IP from
    `kubectl get endpointslice -n default -l kubernetes.io/service-name=kubernetes`
    as a /32. An empty list fails the render.
  • networkPolicy.gitEgress.cidrs and networkPolicy.dexConnectorEgress.cidrs
    default to ["0.0.0.0/0"], which allows every address on 443. Pin them to
    your Git, OIDC, and identity provider addresses.
  • networkPolicy.metricsIngress allows your externally-managed scraper to
    reach operator :8080/:9091, gateway :{grpcPort+1}, bff, and nats :8222
    (the chart ships no monitoring stack; default [] renders no rule).
{{- else }}
================================================================================
  NetworkPolicy
================================================================================
  NetworkPolicy is disabled (networkPolicy.enabled=false).
  Enable with --set networkPolicy.enabled=true after tuning the selectors
  (see values.yaml for details).
{{- end }}

================================================================================
  Tenants
================================================================================
  Creating a Tenant CRD replaces the three hand-authored objects (Group,
  VarroaRoleBinding, and namespace mux) with a single cluster-scoped resource.
  The operator composes: (1) a local Group named tenant-<T> with managed-by and
  tenant-name labels; (2) a VarroaRoleBinding named tenant-<T> scoped to the tenant's
  namespaces; (3) an optional namespace provisioner.

  provisionNamespaces opt-in creates and labels namespaces via the tenancy
  helper.  CAVEAT: in managedNamespaces scoped mode, a runtime-created tenant
  namespace has NO operator/BFF RBAC until Helm re-renders, so
  provisionNamespaces is fully meaningful only in cluster-wide-RBAC mode or
  for namespaces already listed in managedNamespaces.
{{- end }}
